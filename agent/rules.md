# Правила разработки проекта

## 1. Стек технологий

Проект использует следующий стек:

- Java 25
- Gradle
- Lombok
- JUnit 5
- AssertJ

### Зависимости

- Новые зависимости **добавлять не нужно**.
- Все необходимые зависимости для выполнения заданий уже подключены в проекте.
- Перед добавлением любой зависимости необходимо убедиться, что требуемая функциональность не предоставляется уже существующими зависимостями.

---

## 2. Code Style

### 2.1. Форматирование полей класса

Между полями класса необходимо оставлять пустую строку.

Правильно:

```java
public class User {

    private String name;

    private String email;

    private int age;
}
```

Неправильно:

```java
public class User {

    private String name;
    private String email;
    private int age;
}
```

---

### 2.2. Lombok

Для стандартных методов класса необходимо использовать аннотации Lombok.

К стандартным методам относятся:

- getters;
- setters;
- constructors;
- `equals`;
- `hashCode`;
- `toString`.

Если стандартную реализацию метода можно заменить соответствующей Lombok-аннотацией, необходимо использовать Lombok.

Например:

```java
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@EqualsAndHashCode
@ToString
public class User {

    private String name;

    private String email;
}
```

Аннотации Lombok следует размещать **на уровне класса**, если это возможно.

Не следует вручную реализовывать стандартные getters, setters, constructors, `equals`, `hashCode` и `toString`, если для них подходит Lombok.
Проверить возможность использования аннотации `@Data`.

Если параметров в конструкторе больше 3, то следует использовать аннотацию `@Builder`.

## 2.3. Интерфейсы

Для каждого не утилитарного класса (кроме сущностей и моделей) должны быть написаны интерфейсы.

Классы-реализации должны иметь постфикс `impl`, если реализация одна.

---

## 3. Javadoc

### 3.1. Язык

Javadoc должен быть написан **на русском языке**.

Пример:

```java
/**
 * Вычисляет итоговую стоимость заказа с учетом скидки.
 *
 * @param total исходная стоимость заказа.
 * @param discount размер скидки.
 * @return итоговая стоимость заказа.
 */
public double calculateTotal(double total, double discount) {
    return total - discount;
}
```

---

### 3.2. Javadoc для методов интерфейса

Javadoc должен располагаться **над публичными методами интерфейса**.

Пример:

```java
public interface DiscountService {

    /**
     * Вычисляет стоимость заказа с учетом скидки.
     *
     * @param total стоимость заказа.
     * @return стоимость заказа после применения скидки.
     */
    double applyDiscount(double total);
}
```

---

### 3.3. Javadoc для методов, объявленных только в реализации

Если метод не объявлен в интерфейсе и существует только в классе-реализации, Javadoc необходимо писать непосредственно над методом в реализации.

Пример:

```java
public class DiscountServiceImpl {

    /**
     * Проверяет, является ли заказ достаточно большим для получения скидки.
     *
     * @param total стоимость заказа.
     * @return {@code true}, если заказ подходит для скидки.
     */
    private boolean isEligibleForDiscount(double total) {
        return total >= 5000;
    }
}
```

---

## 4. Тестирование

Для написания тестов необходимо использовать:

- JUnit 5;
- AssertJ.

Необходимо использовать уже подключенные в проект зависимости.

При наличии нескольких тестовых сценариев предпочтительно использовать параметризованные тесты JUnit 5, если это делает тесты более компактными и понятными.

Для проверки результатов использовать AssertJ.

Пример:

```java
assertThat(result)
        .isEqualTo(expected);
```
